# SPEC — Wolf Tower (Android first)

Цель: приложение, которое снимает DPI-блокировки для WhatsApp, Telegram и сервисов Google/YouTube.
Платформы: Android (этап 1), Windows и macOS (Electron, этап 2-3).

## Архитектура Android
- profiles/profiles.json — общий для всех платформ список сервисов, доменов, пакетов и стратегий.
- ByeDPI (third_party/byedpi, MIT, вендорен в репозиторий, коммит ba53229) собирается через CMake как исполняемый файл libciadpi.so
  и запускается из nativeLibraryDir как отдельный процесс (SOCKS5 на 127.0.0.1:1080).
- DpiVpnService (VpnService) поднимает TUN, маршрутизирует в него ТОЛЬКО пакеты включённых сервисов
  (addAllowedApplication), трафик TUN отдаётся tun2socks, а тот шлёт его в SOCKS5 ByeDPI.
- tun2socks: hev-socks5-tunnel (MIT, вендорен, коммит 50d7b41), отдельный Gradle-модуль :tun2socks (ndk-build),
  мост — HevTun2Socks.kt. Конфиг hev пишется в filesDir/hev.yml при запуске.
- UDP/QUIC: ByeDPI поддерживает UDP ASSOCIATE (флаг -U его запрещает). Если у ВСЕХ включённых профилей
  block_quic=true, сервис добавляет -U: QUIC быстро падает и YouTube откатывается на TCP.
  Если включён WhatsApp (звонки по UDP), -U не добавляется.

## Решения
- Своя стратегия на каждый сервис: ByeDPI запускается с группами опций `--hosts :домены <стратегия> --auto=none ...`.
  Группа срабатывает по SNI, остальной трафик идёт без изменений. Для сервисов, которые подключаются по IP
  без SNI (клиент Telegram), добавляется отдельная группа `--ipset :диапазоны` (ip_ranges в profiles.json;
  список взят по памяти, сверить с https://core.telegram.org/resources/cidr.txt). Фильтры внутри группы
  работают по "И", поэтому домены и IP идут разными группами.
- Диагностика (Diagnose.kt): если у сервиса 0 успехов, проверяется мимо ByeDPI: DNS телефона и DoH, TCP до IP,
  TLS с именем. Показывает, похоже ли на блокировку по IP, подмену DNS или блокировку по SNI.
- Автоподбор (AutoProbe.kt): по 4 варианта стратегии параллельно, каждый на своём локальном порту;
  проверка = TLS-рукопожатие с проверкой сертификата + HTTP-ответ на тестовых адресах (probe_hosts).
  "none" проверяется первым. Выбор: максимум успехов, при равенстве более ранний в списке.
  Ограничение: проверка не видит замедление потоков уже после рукопожатия.
- Диагностика: CrashInfo сохраняет причину сбоя и показывает её при следующем запуске.
- DNS: hev mapdns (198.18.0.2). Приложения получают фейковые IP, в SOCKS5 уходит имя домена,
  ByeDPI резолвит сам через системный DNS телефона. Если оператор подменяет DNS — нужен DoH (отдельная задача).
- IPv6 пока не туннелируется.

## Открытые вопросы
- Флаги ByeDPI проверены по --help коммита ba53229. Реальную эффективность стратегий проверяет только тест в сети.
- Проверить на реальном телефоне и сети оператора: открывается ли YouTube/Telegram/WhatsApp через туннель.

## Лицензирование
- Офлайн-ключи WT1.<payload>.<подпись> (ECDSA P-256), проверка в License.kt, генератор tools/license/keygen.py.
- Автоматического пробного периода нет: без ключа защита не запускается (проверка в DpiVpnService и в UI).
  Проба = ключ plan=trial с датой окончания и привязкой к устройству (ID = хеш ANDROID_ID).
- ID устройства зависит от ключа подписи APK, поэтому сборки подписываются постоянным ключом (секреты WT_* в GitHub).
- Сверка времени без сервера: ClockGuard.kt берёт заголовок Date у популярных сайтов по HTTPS. Телефон отстаёт
  больше чем на час: ключ удаляется, ставится флаг, повторный ввод блокируется до успешной проверки при нормальных
  часах. Без сети сверки нет (осознанно). Проверки: старт приложения, запуск защиты, активация, раз в 30 минут.
- Публичный ключ: android/app/src/main/assets/license_public_key.txt (по умолчанию заглушка).
- Подробности и ограничения: tools/license/LICENSING.md.

## Проверка доступности (Prober)
- GET / с проверкой, что ответ дочитан до конца или дошёл минимум до 40 КБ (ловит обрыв потока после ~16 КБ).
- Блокировка QUIC (-U) задаётся переключателем в UI; без явного выбора включается, если её хотят все выбранные сервисы.

## Надёжность и самообслуживание (Android)
- Служба работает как foreground (уведомление с кнопкой «Остановить», тип specialUse), плитка быстрых настроек
  (VpnTileService), запрос исключения из экономии батареи, подсказка про автозапуск на Xiaomi/Huawei/Samsung.
- Стратегии запоминаются по сети (NetId.kt): мобильная сеть = MCC+MNC, Wi-Fi = хеш DNS и шлюза (без SSID, чтобы
  не требовать геолокацию; у разных домашних сетей отпечатки могут совпасть). Settings.strategyFor сначала берёт
  значение для текущей сети. При смене сети ByeDPI перезапускается с нужными стратегиями.
- Самопроверка (DpiVpnService.healthCheck): раз в 10 минут тестовые адреса сервисов открываются через работающий
  туннель; при двух неудачах подряд перебираются другие стратегии только для этого сервиса (AutoProbe.score),
  ByeDPI перезапускается. Не чаще раза в 30 минут на сервис. Это замена флагу --auto у ByeDPI, поведение которого
  я не мог проверить без сети.
- DoH (экспериментально, выключен по умолчанию): DohSocksShim стоит между tun2socks (порт 1080) и ByeDPI
  (порт 1082), определяет адреса через DoH (1.1.1.1, затем 8.8.8.8, затем системный DNS) и передаёт ByeDPI IP.
  UDP отклоняется, QUIC и звонки WhatsApp не работают.
- Диагностика (DiagReport.kt): текст для отправки в поддержку без IP-адресов, трафика и ключа.

## Повторное подключение (исправления)
- Порты SOCKS/ByeDPI выбираются свободными при каждом запуске (Ports.kt), ByeDPI проверяется на запуск и открытый порт,
  остановка мягкая, затем принудительная (иначе старый процесс мог держать порт и новый запуск молча не работал).
- Диапазон фейковых адресов hev mapdns случайный на каждый сеанс: адрес, запомненный приложением в прошлом сеансе,
  не должен указывать на другой сайт после перезапуска.
- Сбой запуска туннеля больше не скрывается: служба останавливается и пишет причину в лог.
- Стратегии, подобранные самопроверкой, действуют только в текущем сеансе и не записываются в настройки.

## Версия для компьютера (Windows и macOS)
- desktop/: Electron. Ядро ByeDPI (third_party/byedpi) собирается в CI: Windows кросс-компиляцией MinGW, macOS
  clang для arm64 и x86_64, затем lipo.
- Маршрутизация без VPN: локальный PAC-сервер, в системе включается автонастройка прокси (Windows: реестр
  HKCU AutoConfigURL; macOS: networksetup с запросом пароля администратора). Через ByeDPI идут только домены
  выбранных сервисов; пока защита выключена, PAC отдаёт "напрямую". Если приложение упало, PAC недоступен и
  браузеры идут напрямую; при следующем запуске настройки возвращаются.
- Telegram Desktop: прокси добавляется вручную (SOCKS5 127.0.0.1:18080), IP-группа ByeDPI (ip_ranges) применяется.
- Лицензии те же (ECDSA, ключи WT1.), ID устройства = хеш GUID Windows / UUID macOS / machine-id.
- Не сделано: прозрачный перехват (winws + WinDivert) для приложений без поддержки прокси, самопроверка и
  стратегии по сетям (есть в Android), автозапуск при входе в систему.

## Стабильность WhatsApp (проверено на ciadpi из third_party/byedpi)
- Чат WhatsApp идёт не по TLS, а по протоколу Noise, без SNI. Фильтр `--hosts` смотрит только на SNI/HTTP Host,
  поэтому такое соединение попадало в группу без обхода и уходило целиком. Смещения `+s` на не-TLS трафике
  отменяются (в логе `split cancel`), работают только абсолютные (`-d1`, `-s1`).
- Профиль с `match_all: true` при единственном активном сервисе собирается без `--hosts`: обход применяется ко всему
  трафику приложения (в туннель попадают только выбранные пакеты). При нескольких сервисах работает прежняя схема групп.
- UDP-группа для ByeDPI выбирается без учёта `--hosts`, поэтому `-a1` (1 поддельный UDP-пакет) действует на звонки.
- Новые стратегии: `disorder0`, `split0`, `chain`, `chain+udp`, `disorder0+udp`, `split+udp`, `disorder+udp`.
- Своя строка в стиле ByeByeDPI: имя стратегии `raw:<аргументы>`. Разрешены только флаги обхода
  (`s d o q f t S n l O Q e M r m a Y R`), управляющие (`-i -p -H -j -A -U -D -x` и длинные `--...`) отклоняются.
- Не проверено: пробы (Prober) по-прежнему проверяют только TLS-адреса, проба чата Noise и UDP-проба не сделаны.

## Интерфейс и продукт «только WhatsApp»
- `profiles/profiles.json` содержит один профиль (WhatsApp). Выбора сервисов в Android и desktop нет, Telegram-карточка и QUIC-переключатель убраны (блокировка QUIC ломает звонки).
- Android: интерфейс собран из `Ui.kt` (тёмная тема из цветов иконки, большая кнопка питания, `CopyPill`). Иконка приложения и логотип в шапке сделаны из `icon.png`.
- Лицензия: после активации поля ключа скрываются, остаётся плашка «Лицензия активна / Осталось N дней» (или «Бессрочная»). Сменить ключ можно в «Дополнительно».
- Все кнопки «Копировать»: значок меняется на галочку, подпись на «Скопировано», через 2 секунды возвращается.
- «Дополнительно»: ручной выбор стратегии, своя строка в стиле ByeByeDPI (`raw:...`), лог, диагностика, DoH (только Android).

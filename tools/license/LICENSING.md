# Лицензионные ключи Wolf Tower

Схема: офлайн, без сервера. Вы подписываете ключ приватным ключом (ECDSA P-256), приложение проверяет подпись
публичным ключом. **Автоматического пробного периода нет**: после установки, очистки данных или переустановки
приложение требует ключ. Пробная версия это обычный ключ с `plan=trial`, привязанный к устройству.

## Первая настройка (один раз, на своём компьютере)
    pip install cryptography
    python tools/license/keygen.py init
1. `tools/license/private_key.pem` это СЕКРЕТ. Сделайте резервную копию в надёжном месте, не коммитьте в git
   (`*.pem` уже в .gitignore) и никому не отправляйте. Потеряете, значит не сможете выпускать ключи; утечёт,
   значит ключи сможет выпускать кто угодно.
2. Команда напечатает публичный ключ. Вставьте его целиком в `android/app/src/main/assets/license_public_key.txt`
   вместо заглушки, закоммитьте и пересоберите приложение. Пока заглушка на месте, ни один ключ не принимается.

## Выпуск ключей
    python tools/license/keygen.py issue --trial --device ABCD-EF01-2345            # пробный, 7 дней
    python tools/license/keygen.py issue --trial --days 3 --device ABCD-EF01-2345
    python tools/license/keygen.py issue --days 365 --device ABCD-EF01-2345 --note "Иван"
    python tools/license/keygen.py issue --perpetual --device ABCD-EF01-2345
- Покупатель берёт ID устройства в приложении (блок «Лицензия») и присылает вам.
- Ключ с `--device` работает только на этом устройстве. Ключ без `--device` работает на любом (его можно передать).
  Пробные ключи без `--device` не выпускаются.
- Срок задан датой (от дня выпуска) и действует весь последний день включительно. Повторный ввод того же пробного
  ключа после переустановки пробу не продлевает: дата окончания остаётся прежней.

## Постоянная подпись APK (важно для привязки к устройству)
ID устройства в Android зависит от ключа, которым подписано приложение. Временный debug-ключ GitHub Actions
меняется при каждой сборке, и тогда ID, а с ним и привязанные ключи, ломаются. Нужен свой постоянный ключ подписи:

1. Создайте хранилище (на своём компьютере):
       keytool -genkeypair -v -keystore wolftower.jks -alias wolftower -keyalg RSA -keysize 2048 -validity 10000
   Сохраните файл и пароли. Потеряете, значит не сможете обновлять приложение у пользователей.
2. Закодируйте в base64: Linux/Mac `base64 -w0 wolftower.jks`; Windows PowerShell
   `[Convert]::ToBase64String([IO.File]::ReadAllBytes("wolftower.jks"))`.
3. В GitHub: Settings репозитория, Secrets and variables, Actions, New repository secret. Создайте четыре секрета:
   `WT_KEYSTORE_BASE64` (строка из п. 2), `WT_KEYSTORE_PASSWORD`, `WT_KEY_ALIAS` (wolftower), `WT_KEY_PASSWORD`.
4. После этого сборки подписываются вашим ключом, плюс собирается release-APK. Файл .jks в git не коммитить.
   Переход со старой (debug) подписи на постоянную требует один раз удалить приложение и поставить заново.

## Сверка времени с сетью (без своего сервера)
Когда у телефона есть интернет, приложение сравнивает его часы с заголовком `Date` у нескольких известных сайтов
по HTTPS (ya.ru, google.com, microsoft.com, cloudflare.com, apple.com; сертификат проверяется, подделать нельзя).
Проверка идёт при открытии приложения, при запуске защиты, при активации ключа и раз в 30 минут, пока защита работает.
- Часы телефона отстают от сетевого времени больше чем на час: ключ удаляется (деактивируется), защита
  останавливается, ставится флаг нарушения. Пока флаг стоит, ключ ввести нельзя.
- Флаг снимается, когда при подключении к интернету часы оказываются в норме. Тогда ключ вводится заново (если
  его срок ещё не истёк по настоящей дате).
- Часы опережают сетевое время: ключ не трогается (откат времени назад этим не достигается).
- Нет интернета (или все сайты недоступны): сверка не выполняется, приложение работает по часам телефона.
  Человек с неверным временем, который никогда не выпускает приложение в сеть, может пользоваться: это сознательный
  компромисс вместо платного сервера.
Допуск расхождения 1 час: `ClockGuard.TOLERANCE_MS`. Если у клиента время выставлено вручную и отстаёт, ему
нужно включить автоматическое время (в сообщении об этом сказано).

## Ограничения
- Сверка не работает без сети. Очистка данных приложения сбрасывает ключ и флаг: после этого можно ввести ключ
  офлайн с неверным временем, но при первом же подключении к интернету он деактивируется.
- Приложение можно лишить доступа к сайтам-источникам времени (файрволом, hosts): тогда сверка не срабатывает.
- Решительный пользователь может пропатчить APK. Репозиторий держите приватным.
- Для надёжной защиты, отзыва ключей и учёта активаций нужен сервер.
